# یادداشت بررسی ایستای بستهٔ مرجع Magic Earth

**محدودهٔ بررسی:** این یادداشت فقط از فهرست فایل‌های آرشیو XAPK و نام فایل‌های کتابخانه‌ای قابل مشاهده تهیه شده است. فایل اجرا نشد، کد DEX decompile نشد، محتوای فایل‌های داده خوانده یا استخراج نشد و هیچ فرمت یا دادهٔ اختصاصی برای آبتین‌مپ استفاده نمی‌شود.

| مورد | مشاهدهٔ ایستا |
|---|---|
| حجم XAPK ارسالی | 170,273,000 بایت |
| ساختار انتشار | یک APK پایه، splitهای زبان/تراکم تصویر، و splitهای مستقل `arm64-v8a` و `armeabi-v7a` |
| کد native اختصاصی قابل مشاهده | `libMagicEarthSphereNative.so` |
| مؤلفه‌های ML قابل مشاهده | TensorFlow Lite و کتابخانه‌های Qualcomm SNPE/Hexagon در split arm64 |
| دادهٔ نقشهٔ کشور آماده در XAPK | با فهرست نام فایل‌ها مشاهده نشد |

## برداشت فنیِ مجاز

وجود `libMagicEarthSphereNative.so` نشان می‌دهد رندر یا منطق اصلی نقشه می‌تواند در یک لایهٔ native اختصاصی قرار گرفته باشد؛ اما نام فایل به‌تنهایی **فرمت داده، codec، index یا الگوریتم داخلی** را آشکار نمی‌کند. وجود TensorFlow Lite و SNPE/Hexagon فقط نشان‌دهندهٔ استفادهٔ احتمالی از قابلیت‌های ML روی دستگاه است و مبنایی برای نتیجه‌گیری دربارهٔ فرمت نقشه نیست.

در APK پایه نام‌های `assets/addressinfo/<country>.json` دیده شد؛ این‌ها از نام مسیرشان با دادهٔ کمکیِ کشور/آدرس سازگارند، ولی چون محتوا باز نشده، نباید به‌عنوان دادهٔ نقشه تفسیر شوند. همچنین هیچ نام فایلِ رایجِ map/tile مانند `.mbtiles`، `.pbf`، `.mvt`، `.pmtiles` یا `.abm` در فهرست قابل مشاهدهٔ APK پایه دیده نشد. این نتیجه صرفاً دربارهٔ **این XAPK** است؛ دادهٔ نقشه ممکن است بعداً دانلود شود یا در فضای خصوصی برنامه قرار گیرد که خارج از محدودهٔ بررسی بود.

> نتیجهٔ عملی: از این فایل نمی‌توان codec یا ساختار فایل نقشهٔ اختصاصی Magic Earth را استخراج یا بازسازی کرد؛ و آبتین‌مپ نیز نباید چنین کاری انجام دهد.

## اثر مستقیم بر ABM2 مستقل آبتین‌مپ

هدف مطلوب کاربر—باز شدن سریع نقشه، pan و zoom آنی، و دانلود کاملِ جداگانهٔ هر کشور—با یک معماری مستقل و استانداردشدنی به‌دست می‌آید، نه با تقلید از فرمت دیگران. طراحی ABM2 باید به‌صورت زیر ادامه یابد:

| لایه | تصمیم ABM2 مستقل |
|---|---|
| فایل دانلودی | یک فایل `*.abm` برای هر کشور/بخش، با header و index قابل seek |
| تصویر نقشه | MVT از پیش‌ساخته در chunkهای فشرده؛ بدون تبدیل PBF یا raster-rendering داخل APK |
| نمایش | MapLibre فقط tile آمادهٔ viewport را دریافت می‌کند؛ تبدیل گسترده به GeoJSON انجام نمی‌شود |
| جست‌وجو و routing | index و graph مستقل از لایهٔ نمایش نگهداری می‌شوند |
| به‌روزرسانی | patch مستقل ABP2 بر اساس chunkهای تغییرکرده، نه دانلود مجدد کل کشور |
| مسیر انتقال v1 | local loopback tile bridge برای رساندن MVT آماده از فایل ABM2 به MapLibre؛ ABM v2 فعلی تا قبولی benchmark حذف نمی‌شود |

مسیر فعلی ABM در Flutter برای هر viewport tileها را به GeoJSON تبدیل می‌کند. این تبدیل همان بخش پرهزینه‌ای است که ABM2 باید حذف کند. مرحلهٔ بعدیِ قابل تست، ساخت یک region واقعیِ چند-tile، نصب آن در اپ، و اندازه‌گیری زمان first frame و رفتار pan/zoom روی دستگاه Android است؛ prototype تک-tile موجود، نتیجهٔ APK یا نقشهٔ کامل کشور نیست.

## مرزهای بررسی

این گزارش عمداً شامل dump کد، disassembly، استخراج asset data، تحلیل encryption، مهندسی معکوس فایل نقشه، یا راهکار سازگاری با فرمت اختصاصی نیست. تنها از الگوی سطح‌بالای «نقشهٔ آمادهٔ دانلودی + نمایش سریع روی دستگاه» به‌عنوان هدف محصول الهام گرفته می‌شود.
