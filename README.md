# سازندهٔ نقشهٔ تک‌فایلی ABTINMAP

هر بستهٔ قابل دانلود در نهایت یک فایل `XX.abm` است؛ برای نمونه `IR.abm` یا `TR.abm`. کشورهایی که منبع رسمی آن‌ها از ابتدا منطقه‌بندی شده است، همچنان با بسته‌های ناحیه‌ای مستقل ارائه می‌شوند؛ مانند `US-NE.abm`، `US-WE.abm` و `RU-SIB.abm`. اپ همهٔ این بسته‌ها را زیر کشور مادر و با همان پرچم نشان می‌دهد.

فایل ABM شامل گراف مسیریابی، شاخص جست‌وجوی آفلاین و اطلس تصویری چندزومیِ ازپیش‌رندرشده است. اطلس و پیش‌نمایش کوچک به انتهای ABM افزوده می‌شوند و با footer هفتادودوبایتی `ABTATLS2` قابل کشف هستند. بنابراین کاربر برای هر نقشه فقط همان یک فایل ABM را دانلود می‌کند.

## ساخت قابل‌ادامه برای همهٔ کشورها

تمام کشورها، بدون استثنا، از یک الگوی پایدار استفاده می‌کنند. هر کشور به شبکهٔ **۴×۴، معادل ۱۶ بخش جغرافیایی** تقسیم می‌شود. هر بخش در یک GitHub job جدا با **دقیقاً یک renderer و یک worker WebP** ساخته می‌شود. پس از پایان موفق، کاشی‌ها و فایل `complete.json` همان بخش به‌صورت checkpoint در ریلیز داخلی `map-checkpoints-v1` ذخیره می‌شوند.

> اگر runner خاموش یا job لغو شود، اجرای بعدی فقط بخش ناقص را می‌سازد. هیچ checkpoint سالمی دوباره رندر نمی‌شود. در عین حال، هر checkpoint شامل **اثر انگشت نسخهٔ PBF رسمی** (ETag، زمان تغییر و حجم) است؛ با به‌روزرسانی دادهٔ Geofabrik، checkpoint قبلی خودکار نامعتبر می‌شود تا نقشهٔ قدیمی دوباره منتشر نشود.

پس از کامل شدن ۱۶ checkpoint، یک job ادغام آن‌ها را به `XX.amap` تبدیل می‌کند و سپس مرحلهٔ ساخت بسته، گراف و شاخص را تولید کرده و atlas آماده را بدون شروع renderer تازه به فایل `XX.abm` الحاق می‌کند. در پایان، manifest، فایل کامل و در صورت امکان patch افزایشی در GitHub Release عمومی منتشر می‌شوند.

| جزء | رفتار |
|---|---|
| `tools/checkpoint_render.py` | رندر دقیقاً یک stage یا ادغام همهٔ stageهای تأییدشده |
| `tools/build_country_package.py --prebuilt-atlas` | ساخت ABM نهایی با atlas آماده، بدون رندر تکراری |
| `map-checkpoints-v1` | ریلیز داخلی برای checkpointها؛ فایل نصب کاربر نیست |
| `maps-v3` یا تگ انتخابی | ریلیز عمومی شامل ABM، patch و `manifest.json` |

## اجرای workflow

از بخش **Actions**، workflow با نام **Build Abtin Map (resumable checkpoints)** را اجرا کنید. در ورودی `countries`، کدها را با ویرگول وارد کنید؛ برای مثال:

```text
IR,TR,IQ
```

هر اجرا حداکثر ۱۵ کشور را می‌پذیرد، زیرا ۱۶ stage برای هر کشور ساخته می‌شود و GitHub برای یک workflow سقف job دارد. برای ساخت همهٔ فهرست کشورها، آن‌ها را در چند اجرای حداکثر ۱۵تایی اجرا کنید. ورود `all` عمداً غیرفعال است تا workflow از سقف GitHub عبور نکند.

هر job حداکثر ۳۵۰ دقیقه تنظیم شده است، اما طراحی باید stageها را کوتاه‌تر از سقف runner نگه دارد. اگر یک stage بسیار سنگین شد، `grid_size` در `checkpoint_render.py` را می‌توان افزایش داد؛ خروجی نهایی و قرارداد فایل ABM تغییری نمی‌کند.

## به‌روزرسانی و patch

workflow پس از ساخت ABM جدید، نسخهٔ قبلی همان کشور را از release دریافت می‌کند و در صورت وجود، patch باینریِ افزایشی می‌سازد. اپ فقط وقتی patch را نصب می‌کند که هش نسخهٔ نصب‌شده با `base_sha256` یکسان باشد؛ در غیر این صورت دانلود کامل ABM انجام می‌شود. هش نهایی پیش از جایگزینی اتمیک بررسی می‌شود تا قطع اینترنت یا patch نامعتبر فایل فعال را خراب نکند.

## بخش اطلس رندرشده در ABM

| بخش داخل ABM | مصرف در اپ |
|---|---|
| هدر، گراف و شاخص ABTINMAP | مسیریابی و جست‌وجوی آفلاین |
| SQLite اطلس WebP | نمایش نقشهٔ آماده |
| پیش‌نمایش overview | نمایش سریع پیش از استخراج atlas |
| footer `ABTATLS2` | یافتن و استخراج امن atlas از همان ABM |

اپ فایل atlas جداگانه‌ای دانلود نمی‌کند. با انتخاب هر کشور یا منطقه، فقط `XX.abm` دریافت می‌شود.
