# یادداشت بررسی ایستای بخش‌های نقشهٔ ارسالی

این گزارش فقط از نام فایل‌ها، حجم، signature ابتدایی و header محدود هر فایل تهیه شده است. هیچ فایل اجرایی اجرا نشد، هیچ دادهٔ نقشه decode یا استخراج نشد، و هیچ parser یا سازگاری با این فرمت ساخته نمی‌شود.

| گروه | فایل‌ها | مشاهدهٔ سطح‌بالا |
|---|---|---|
| ایران | `irn.2dc`, `irn.fts`, `irn.hmp`, `irn.ne0`, `irn.ne1`, `irn.ne2`, `irn.poi`, `irn.pak` | چند container با familyهای header متفاوت، به‌همراه archive/index منطقه‌ای مجزا. |
| جهان/کلاس | `wcl.ne1`, `wcl.ne2`, `wcl.ne9`, `wcl.pak` | سه container map-like و یک archive/index جداگانه. |
| archive | `wcl.pak` | header قابل مشاهدهٔ `pak1` و نام‌های archive داخلی مانند `wcl.ar0`, `wcl.ar1` همراه با مقدارهای offset/size دیده می‌شود. |

## یافته‌های قابل اتکا

فایل‌های `*.ne*`، `*.2dc` و `*.fts` در header خود magic سازگار با `MAP3` دارند؛ `irn.poi` magic سازگار با `MAP2` و `irn.hmp` magic سازگار با `MAPC` دارد. وجود field تکراری `0x4000` در headerهای MAP2/MAP3 و وجود چند مقدار offset-like در آغاز فایل، با طراحی chunk/index سازگار است، اما **برای تعیین معنای دقیق fieldها کافی نیست**.

`irn.pak` با حجم 94,592,488 بایت همان header family قابل مشاهدهٔ `pak1` را دارد و entryهای سطح‌بالایی مانند `irn.ar0`، `irn.ar1`، `irn.ar2`، `irn.ar9` و `irn.header` را در table ابتدایی نام‌گذاری می‌کند. `wcl.pak` نیز همین الگو را با نام‌های `wcl.ar*` نشان می‌دهد. از این مشاهده فقط می‌توان وجود archive/index منطقه‌ای با entryهای offset/size را نتیجه گرفت؛ نه codec، schema داخلی یا معنای دادهٔ هر entry.

از روی نام فایل‌ها می‌توان گفت `poi` احتمالاً دادهٔ نقطه‌ایِ مجزا است، اما نقش دقیق `ne*`، `2dc`، `fts` و `hmp` بدون decode مشخص نمی‌شود و در این بررسی نتیجه‌گیری قطعی دربارهٔ آن‌ها انجام نشده است.

> نتیجهٔ معماری: یک دانلود منطقه می‌تواند از چند resource typed با یک catalog کوچک و table قابل seek تشکیل شود. این یک اصل عمومی معماری است، نه مشخصات یا تقلید از فایل‌های ارسالی.

## اثر بر ABM2 مستقل آبتین‌مپ

ABM2 باید همچنان یک فایل `*.abm` واحد برای کاربر بماند، اما داخل آن index قابل seek و chunkهای typed مستقل داشته باشد: `IDX2` برای lookup، `VCH2` برای tile برداری آماده، `RCH2` برای graph، `SRH2` برای index جست‌وجو و بخش POI جدا. manifest دانلود فقط id، version، SHA-256، حجم، bounds و endpoint را نگه می‌دارد.

این طراحی مزیت معماری چندبخشی را نگه می‌دارد، اما فایل داخلی، codec، magic، نام‌گذاری و دادهٔ مستقل آبتین‌مپ را دارد و با فرمت ارسال‌شده سازگار یا وابسته نیست.
